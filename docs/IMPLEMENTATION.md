# 本地三维工作室：产品与实施决定

## 产品定义
用户通过原有 DeepSeek 对话给出文字或参考素材。插件不创建第二个模型账号，不调用商业三维生成 API。DeepSeek 负责理解与编排，本地现成项目负责图像生成、几何生成、动画与渲染。优先用户指定和已注册的本地项目，缺少时获取官方上游项目，安装在专用目录和隔离环境。

## 最新入口要求（优先级最高）
- 一句话普通请求：不先盘问；采用可撤回的默认值，通过现成 Blenderwright 工具生成基础模型样例，再询问特别需求和精细化。
- 明确特别需求：进入 grill-me 式访谈，每轮询问最影响结果的 1—3 个问题，已有事实不重问，硬件由插件检测。
- 访谈区分视觉细节、参考还原和尺寸精度；把答案整理为用途、主体、风格、结构、材质、细节、动画、交付规格及不可妥协项。
- 访谈结束提交简短需求确认，随后生成样例；正式制作仍受样例批准控制。
- 已完成的基础模型和用户反馈保留为修订历史。

## 必须到达的状态
`draft → previewing → awaiting_review → approved → building → completed`

任一运行阶段可进入 `failed` 或 `cancelled`。用户修改需求、样例或质量设置后产生新 revision，并清除旧审批。缺少依赖进入可恢复的阻塞状态，保留需求与参考素材。重复的完整生成不得由过期批准触发。

## 交互决定
- 样例必须显示来源与能力：程序化三维预览、生成式概念图、图生模型预览、静态视频重建、动态近似复刻。
- 批准前显示具体修订版、后端、分辨率、时长、帧数、模型与输出内容。`rule/name-object-scope-consequence`
- 正式构建必须经过 Harness 的人机交互，不能让模型传一个 `approved: true` 绕过。`rule/irreversible-action-safeguard`
- 样例可反复调整；批准当前修订版以后才执行正式制作。`rule/preserve-user-input`
- 未安装工具、未知显存、生成失败、取消、重启恢复都给出原因和下一步。`rule/cover-reachable-states`、`rule/error-states-recovery`
- 复用对话中的输入、图片和视频路径，不要求重复填写。`rule/no-redundant-entry`
- 不增加独立账号、付费界面或无必要的设置步骤。`rule/smallest-intervention`

## 依赖与实现边界
1. Node 标准库：项目状态、路径限制、硬件信息、进程控制、任务日志。
2. Blenderwright：现有建模、材质、骨骼、动画、摄影机及渲染工具；由 DSH 官方 MCP 客户端连接。只编写独立实例启动适配，不自写三维引擎。
3. FFmpeg / FFprobe：视频抽帧、音频、合成；没有时明确报错。
4. TripoSR：可选单图重建，本地仓库与权重。
5. Hunyuan3D 2.1：可选单图几何与 PBR，本地仓库与权重，独立 Python 环境。
6. 本地 ComfyUI：优先用户已有工作流；可选概念样图、文生三维或视频相关工作流，不要求 key；仅接受本地地址，外部节点和权重下载另列来源。
7. COLMAP：可选静态多视图视频重建；人物运动和复杂镜头依赖 DeepSeek 提交可执行的近似场景及运动方案。

## 将来需单独批准的验证
一次离线检查可包含：Node 单元/状态机测试、Python 语法编译（输出到临时目录）、安装包结构和 Harness 契约检查。无需真实模型、无需调用 DeepSeek、无需 GPU 渲染。

实际 Blender 渲染、硬件探测、本地模型推理和 Harness 安装验收分别明确范围后再执行。本次实施不自动执行这些检查。
